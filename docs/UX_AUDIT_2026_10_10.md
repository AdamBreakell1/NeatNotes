# RecallStride UX audit — 10 October 2026

## Scope and decision

Audit base: `32272263be405a928999d01cd1c19c2832e77b74`. This inspection covers the public landing page, first entry, Today, course topics and flashcards, all four Practice activities, Code studio and projects, Progress, Notes, search, onboarding, account forms, Settings, pricing, help and dialogs. Source inspection is combined with local desktop/mobile inspection and disposable synthetic accounts; production student data is not a test fixture.

The current five destinations, visible Practice overview, direct Code entry, topic catalogue, focused flashcards and supporting Notes placement form a coherent product. Keep these, the existing visual identity, working local draft preservation and reduced-motion support. No wholesale redesign, extra navigation layer or new dashboard is justified by this inspection. The improvements below correct demonstrable mismatches between a control's promise and its behaviour, or remove a concrete keyboard/recovery barrier.

## Guidance used

These are implementation choices informed by primary guidance, not a claim of accessibility certification. [W3C's modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) describes containing keyboard focus and returning it on close. [W3C Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) explains why sticky or overlay content must not hide focused controls. [GOV.UK's validation guidance](https://design-system.service.gov.uk/patterns/validation/) supports actionable errors close to the input/action, retaining entered information and helping users recover.

Baseline local inspection images are in `/tmp/recallstride-ux-2026-10-10/`. The existing navigation research and previous regression coverage are retained in `navigation-redesign-audit.md`; this audit does not repeat its redesign or claim new student research.

Verification and password reset now use a shared RecallStride template with the RS mark, a clear action button, a short explanation, the correct 24-hour or 30-minute expiry, guidance for an unrequested email and a full fallback URL. Both include a complete plain-text alternative. The layout uses inline styles and presentation tables, with no external images or tracking. Existing sender configuration, tokens, delivery handling and account behaviour are retained.

The real signup/reset routes were verified with an injected mail transport and an in-memory account, without sending an email. Desktop and 390 px browser previews have no horizontal overflow. This confirms the generated template and integration; it does not claim testing in every email client.
