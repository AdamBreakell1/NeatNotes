# Decision: bounded local formative practice

13 September 2026. Retain Node/Express/SQLite and vanilla browser JavaScript. Use an original explicit lexer → parser → AST → interpreter in a dedicated disposable Web Worker. Deterministic execution never calls an LLM or runs generated host code. Only an allowlisted set of scalar, array and routine operations exists. Map-based environments never expose host objects or prototype/property lookup. The worker response adds CSP restrictions against connections; the language itself has no host capabilities.

Updated 7 October: latest task selection resumes, the delayed transfer suggestion opens its task, stale versions remain stale through edits/reload (including empty source), and light/dark text uses the existing theme surfaces. Inline errors accompany the keyboard error list. Pilot events require account consent in the client and server, contain enums/IDs only, and remain separate from mastery. Policy documents are visible local drafts with keyboard-contained dialog focus. Release evidence and external gates are in [RELEASE_REPORT.md](../RELEASE_REPORT.md).

The researched alternatives are in [the source register](SOURCES_AND_CONTRACT.md). The GCSE Rust interpreter has a qualification mismatch, CLI assumptions and GPL obligations; the CIE editor has a different grammar and an unverified licence. Monaco excludes mobile. CodeMirror is a viable later editing adapter, but would add a bundling/dependency pipeline to this small plain-JS app. The first adapter uses a labelled native textarea with a separate escaped highlighting layer, line gutter, plain-text switch, indentation buttons, keyboard navigation and bounded undo/redo. This keeps a native accessible input and touch keyboard. It needs real screen-reader/device testing before promotion. Syntax colouring never determines correctness.

No server execution is warranted for this initial draft bank. Client outcomes are explicitly untrusted local practice: separate storage, no call into learning_evidence, review_schedules, protected entitlements or official marking. Authentication, existing deck access and version-specific content release are checked on every task/attempt request. Draft bank preview requires an explicit non-production flag; production cannot use it. No hidden tests are claimed: cases delivered to a browser can be inspected.

The source, fixtures, prediction and rubric checklist stay in account-scoped browser storage for up to 30 days after editing; they are never analytics. Export/erase controls are available in the coding area. Sign-out and account deletion clear this account's coding storage; other tabs receive a session-change signal and discard their in-memory worker/editor. Local storage is not encryption: users on shared computers should sign out. Server metadata contains only task/version/attempt ID, assistance counters, case IDs/outcome enums and local provenance. Retry requests are idempotent; conflicting payloads reuse no receipt. Server retention is 30 days, expired records removed on startup and daily; foreign keys cascade on account deletion. Browser retry queues retain the identical record; changing source starts a new result record.

Draft access/version/withdrawal is revalidated online before resuming, running, checking or syncing. A connectivity failure leaves the draft available for editing/export, disables dependent checks and offers retry. A removed/version-changed task preserves the old source for manual recovery, never silently substitutes new text. Results belong to an exact source revision; edits invalidate the displayed result. No blind copying of guest drafts into an account.

Run/Check execute in new workers; Stop, task change, mode change, account change and section exit terminate the old worker. Request tokens suppress late responses. Count empty loops, expression traversal, routine calls and array/string allocation. A main-thread watchdog backs up internal work/time/depth limits. Source, fixtures and cases are bounded before worker posting and again inside the engine. Rendering uses textContent or escaped spans. Worker import is a fixed versioned engine URL, never a student-provided import.

The task bank and benchmark are drafts. Each task has examples, expected-output comparison rules, equivalent algorithms, deliberately faulty variants, progressive hints and a reasoning checklist. No marks are emitted. A passing finite test suite is evidence only about those cases. Specimen analysis informs task structure; no proprietary questions or commercial code were copied.

Trusted evaluation would require a separate authenticated/rate-limited submission queue, disposable OS-isolated worker processes with memory/CPU/wall quotas, no database/network/provider access, version pinning, independent benchmark validation and abuse monitoring. Node worker threads alone do not establish a strong security boundary. Estimate measured per-submission resources and support costs before approving that future architecture.
