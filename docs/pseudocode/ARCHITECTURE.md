# Embedded coding workspace

Updated 7 October 2026 after the user's request for complete, usable coding practice. This replaces the earlier eight-task preview design. The existing Node/Express/SQLite and vanilla JavaScript stack is retained; no dependency was added.

The workspace contains 51 core exercises adapted from the five supplied CodingTasks worksheets, their optional higher-or-lower game, and eight existing RecallStride exercises: 60 tasks total. All tasks have instructions, starter code or data, examples, public functional checks, hints and a worked solution. Tasks are available to guests and signed-in students independently of their revision deck. Authentication is still required to read or write account attempt history. Coding access does not change paid revision-deck access.

Students write in an accessible native textarea with escaped syntax colouring, line numbers, undo/redo and indentation controls. Task, Files and Language panels sit beside the editor on desktop and above it on mobile. The Console accepts input as the program asks for it. Optional preloaded inputs are available. Check task runs the published cases against the original task files; it never replaces the student's edited files. A separate Variables view shows bounded after-statement snapshots, not a claim of live step debugging.

The original lexer → parser → AST interpreter runs inside a disposable Web Worker. It never executes JavaScript supplied by a student, calls an LLM, exposes host objects, or gives student code filesystem/network access. It supports selection including CASE, stepped loops and loop exits, strings, 1D/2D/3D arrays, local by-value routines, numeric functions, seeded random integers, virtual text files and timed output. Every operation is explicitly allowlisted. Worker CSP prohibits network connections.

When input is exhausted, the engine returns partial output, file state and the next prompt. The controller retains an immutable starting-file snapshot and random seed, adds the submitted input and replays in a fresh worker. Deterministic replay preserves random cards and side effects; the console appends only new events. Stop, task change, account change and leaving coding terminate the worker and cancel playback. A generation token rejects late responses. wait/sleep record bounded delays; the main thread plays output using cancellable timers rather than blocking the interpreter.

Limits remain hard ceilings: 16,384 source characters, 6,000 tokens, 64 parse/AST depth, 1,000,000 work units, 1.5 seconds CPU wall time per case, 4,096 allocated array cells, 1,000 output lines/65,536 output characters, 20 virtual files/65,536 file characters, 100 input values/8,192 total characters and 30 seconds of recorded output delay. Parent watchdogs terminate Run at 3 seconds and Check at 22 seconds. Empty loops, allocations, expression evaluation and size-based operations consume work. Limit overrides may only lower a ceiling.

Source, virtual files, input fixtures, planning notes and assistance stay in owner-scoped local storage for 30 days after editing. Guest storage is separate; signing in does not copy it into the account. Sign-out/account deletion clear that account's browser drafts and signal other tabs to close their editor. Projects can be downloaded and reopened with source plus virtual files; imports validate format, names and size before replacing anything. Account exports contain metadata only; a separate local export contains this device's drafts.

Check receipts store task/version identifiers, outcome enums and assistance counters. They are explicitly untrusted local practice and cannot become marks, grades or learning/mastery evidence. Retention, idempotent retries, account isolation and foreign-key deletion remain unchanged. Consent-controlled analytics accept only approved event enums and IDs, never source, filenames, input or output. Existing academic review records remain descriptive metadata; no reviewer or approval was fabricated.

The linked school starter files returned HTTP 401. Data printed in the worksheets was transcribed; missing fixtures were reconstructed and labelled inside the relevant task. State populations are fictional classroom values. Planet data is a fixed classroom dataset including historical moon counts. Original classroom verses replace the supplied song excerpt. Reference-site behaviour informed the workflow; no proprietary editor or interpreter was copied or embedded.
